## 1. Qué estamos resolviendo

El problema es el siguiente: dado un grafo de N=10 osciladores de Kuramoto con fases
iniciales aleatorias, encontrar la **topología de red** (qué aristas existen) que maximice
la función de recompensa:

```
R(W) = conectividad(W) - r(W, theta_0)
```

donde:
- `conectividad(W) = (min_degree + 1) / N` — qué tan bien conectado está el nodo más aislado
- `r` — parámetro de orden de Kuramoto: `|mean(exp(i*theta))|` al final de la simulación  
  - `r ≈ 1`: todos los osciladores están **sincronizados** (fases iguales)
  - `r ≈ 0`: osciladores **desincronizados** (fases dispersas)

El objetivo es maximizar R: **alta conectividad + baja sincronización**.

Esto es una tensión inherente: agregar aristas tiende a **aumentar** la conectividad
pero también a **aumentar** la sincronización (más caminos para que las fases se alineen).
Encontrar el balance óptimo es el desafío central del problema.

## 3. Diagnóstico: por qué el modelo no aprende

### 3.1 Alta varianza del gradiente (problema central de REINFORCE)

REINFORCE es el algoritmo de policy gradient más básico. Su gradiente es:

```
∇J(θ) = E[ ∇log π(a|s) * G_t ]
```

donde `G_t` son los retornos descontados. El problema es que la **varianza de
este estimador es muy alta**, especialmente cuando:

1. El estado inicial (grafo aleatorio + fases aleatorias) varía mucho entre episodios
2. La función de recompensa es ruidosa (depende de una simulación numérica)
3. Los retornos no están centrados en cero antes de la normalización

**Efecto observado**: el agente hace cambios en los pesos pero la señal de gradiente
es tan ruidosa que no puede extraer cuál topología es mejor. Con 200 episodios y
alta varianza, la convergencia no es garantizable.

### 3.2 Sincronización casi inevitable en el Modelo de Kuramoto

El modelo de Kuramoto sin frecuencias naturales heterogéneas (es decir, con
`omega_i = 0` para todos los nodos, que parece ser el caso aquí) tiende
naturalmente a sincronizarse en **cualquier grafo conectado**. Esto implica:

- Si el grafo tiene al menos un componente conectado, `r → 1` inevitablemente
- La única forma de mantener `r < 1` es con un grafo **desconectado** o con
  nodos aislados
- Pero grafos desconectados tienen baja conectividad, lo que penaliza la recompensa

Esto crea un **dilema estructural en la función de recompensa**: las topologías
que dan baja sincronización son exactamente las que tienen baja conectividad,
haciendo que ambos términos se compensen y la recompensa total nunca supere
cierto umbral.

**La pregunta clave para el problema**: ¿existe alguna topología que logre alta
conectividad Y baja sincronización? Si no la hay, el problema es inherentemente
difícil y la función de recompensa necesita ser revisada.

### 3.3 El GCN recibe una señal de entrada casi constante

En todos los episodios, el tensor de entrada al GCN es:
- `theta`: fases aleatorias uniformes en `[-π, π]` → esperanza ≈ 0
- `W`: matriz de adyacencia aleatoria → en promedio, muy similar entre episodios

El GCN no tiene memoria entre episodios. Cada episodio empieza desde cero con
entradas casi indistinguibles. El modelo no puede "recordar" qué topologías
funcionaron antes.

### 3.4 Espacio de acción grande y undirected

Con N=10 hay 45 posibles aristas. Cada paso elige una de 45 acciones con
softmax. Al inicio del entrenamiento, el modelo muestrea casi uniformemente
(alta entropía). Con solo 20 pasos por episodio y 200 episodios totales,
el agente hace 4000 acciones para explorar un espacio de topologías de tamaño
`2^45 ≈ 3.5 × 10^13`. La exploración es mínima.

## 5. Pasos concretos para mejorar

### Paso 1 (inmediato): Agregar frecuencias naturales heterogéneas

**Qué hacer**: modificar `funcion_recompensa.py` para asignar frecuencias naturales
`omega_i` distintas a cada nodo. El modelo de Kuramoto original es:

```
d(theta_i)/dt = omega_i + sum_j [ W_ij * sin(theta_j - theta_i) ]
```

Con `omega_i` heterogéneos (ej: distribuidos uniformemente en `[-1, 1]`), la
sincronización ya no es inevitable. Grafos con alta conectividad pueden mantener
`r < 1` si la diversidad de frecuencias es suficiente.

**Impacto esperado**: la tensión entre conectividad y sincronización se vuelve más
rica. Ahora existen topologías que logran conectividad media-alta con r bajo.

**Cambio en el código** (`funcion_recompensa.py`):
```python
def evaluar_grafo(W, theta_inicial=None, omega=None):
    n = W.shape[0]
    if theta_inicial is None:
        theta_inicial = np.random.uniform(-np.pi, np.pi, n)
    if omega is None:
        omega = np.random.uniform(-1.0, 1.0, n)  # NUEVO
    # en simular(): nueva_theta = theta + (omega + vel) * dt
```

### Paso 2 (inmediato): Reemplazar REINFORCE con Actor-Critic (A2C)

**Problema que resuelve**: la alta varianza del gradiente.

**Qué hacer**: agregar una red "crítica" (Critic) que aprenda a estimar el valor
esperado `V(s)` de cada estado. El gradiente se convierte en:

```
∇J(θ) = E[ ∇log π(a|s) * (G_t - V(s)) ]   <- la diferencia reduce varianza
```

El término `G_t - V(s)` se llama **advantage** y tiene varianza mucho menor
que `G_t` solo.

**Arquitectura sugerida**: compartir el GCN entre Actor y Critic, con dos
cabezas de salida (política y valor). Esto es más eficiente que tener dos redes
separadas.

### Paso 3 (importante): Usar la misma distribución inicial de grafos

Actualmente cada episodio empieza con un grafo **completamente aleatorio**.
Esto hace que el agente nunca pueda explotar lo aprendido en episodios anteriores.

**Opción A**: empezar siempre desde el grafo vacío (sin aristas). El agente construye
la topología de cero cada episodio. Más interpretable, menos ruido.

**Opción B**: curriculum learning — empezar simple (grafos pequeños, menos nodos)
e ir aumentando la complejidad.

### Paso 4 (importante): Baseline con búsqueda exhaustiva o heurística

Antes de seguir mejorando el RL, **medir el óptimo real** para N=10. Con 45 aristas,
se pueden muestrear aleatoriamente 10,000–100,000 topologías distintas y evaluar
su recompensa. Esto da:

1. Un **baseline** real contra el que comparar el agente
2. Insight sobre cuál es la topología óptima real
3. Entender si el problema tiene solución "interesante" con la función de recompensa
   actual

**Código sugerido** (archivo `busqueda_aleatoria.py`):
```python
import numpy as np
from funcion_recompensa import evaluar_grafo

def grafo_aleatorio(n):
    W = np.triu(np.random.randint(0, 2, (n, n)), k=1)
    return (W + W.T).astype(float)

N, MUESTRAS = 10, 50000
mejor = -np.inf
mejor_W = None
for _ in range(MUESTRAS):
    W = grafo_aleatorio(N)
    theta = np.random.uniform(-np.pi, np.pi, N)
    rew, conn, r = evaluar_grafo(W, theta)
    score = float(np.mean(rew))
    if score > mejor:
        mejor = score
        mejor_W = W.copy()
```

### Paso 5 (mediano plazo): Normalización del espacio de observación

El GCN actualmente toma como entrada:
- Fases `theta ∈ [-π, π]`
- Adyacencia binaria `W ∈ {0, 1}`

Mejoras:
- Transformar fases a `(sin(theta), cos(theta))` — representación circular que
  el GCN puede procesar sin discontinuidad en ±π
- Normalizar W por grados (ya está contemplado en la GCNConv personalizada)
- Agregar como feature el grado de cada nodo

### Paso 6 (mediano plazo): Reformular la función de recompensa

La recompensa actual `conectividad - r` tiene un problema: `r` es siempre ≈ 1,
lo que hace que la recompensa sea efectivamente `-0.6` a `-0.8` casi siempre.
No hay gradiente informativo.

**Opciones**:
1. **Penalizar la varianza de fases** en lugar de `r`: `- std(theta_final)` favorece
   configuraciones donde las fases divergen más
2. **Recompensa por paso**: en lugar de evaluar solo al final, dar recompensa en
   cada iteración de Kuramoto → señal más densa
3. **Función multi-objetivo**: maximizar simultáneamente conectividad global
   (algebraic connectivity = segundo eigenvalor del Laplaciano) y minimizar r

### Paso 7 (largo plazo): PPO en lugar de REINFORCE

Proximal Policy Optimization (PPO) es el estándar actual para problemas de
policy gradient con espacios de acción discretos. Ventajas sobre REINFORCE:
- Usa mini-batches y múltiples épocas por episodio → más eficiente en muestras
- Clipping del ratio de probabilidad → entrenamiento más estable
- Incluye un Critic por diseño

## 7. Contexto teórico

### Modelo de Kuramoto
El modelo de Kuramoto describe la dinámica de N osciladores acoplados:

```
d(theta_i)/dt = omega_i + (K/N) * sum_j [ A_ij * sin(theta_j - theta_i) ]
```

El parámetro de orden `r = |mean(exp(i*theta))|` mide la coherencia de fases.
En la versión implementada, `K=1`, `omega_i=0` para todos, por lo que **siempre
habrá sincronización completa en cualquier grafo conectado**. Esta es la
limitación más importante del setup actual.

Referencia clave: *Kuramoto (1984), "Chemical Oscillations, Waves, and Turbulence"*.
Para la relación topología-sincronización: *Arenas et al. (2008), "Synchronization
in complex networks", Physics Reports 469(3):93-153*.

### REINFORCE y Policy Gradient
REINFORCE (Williams, 1992) es el algoritmo base de policy gradient. Su problema
de alta varianza es bien conocido y motivó el desarrollo de:
- Actor-Critic methods (Konda & Tsitsiklis, 2000)
- PPO (Schulman et al., 2017)
- SAC para espacios discretos

La normalización de retornos (ya implementada) reduce la varianza pero no la
elimina. El paso siguiente natural es usar un baseline aprendido (Critic).

### GCN para optimización combinatoria
La arquitectura GCN + Policy Gradient para optimización en grafos está bien
estudiada. Trabajos relevantes:
- *Khalil et al. (2017), "Learning Combinatorial Optimization Algorithms over Graphs"*
  (usa DQN + estructura2Vec)
- *Kool et al. (2019), "Attention, Learn to Solve Routing Problems"* (Transformer
  en lugar de GCN)

La clave en estos trabajos es que el estado del problema es **fijo** durante el
episodio (el grafo no cambia externamente). En nuestro problema, el grafo evoluciona
con las acciones del agente, lo que es un MDP estándar pero con observaciones
que cambian rápidamente.
